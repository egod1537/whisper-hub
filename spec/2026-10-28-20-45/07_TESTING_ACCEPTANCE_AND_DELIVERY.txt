PHASE 07 - TEST, QA AND CODEX HANDOFF

AUTOMATED TESTS
- API client: bearer auth, response parsing, errors, abort, downloads.
- Upload: required file, required format, correctly serialized multipart language/formats, no double submit, idempotency behavior.
- Queue: queued->processing->completed, failed/retry, queued/cancel, processing/cancel pending, polling/backoff and 401.
- Results: text preview is safely escaped, format-specific authenticated download, long transcript truncation, expired/missing result.
- Responsive smoke: 360px / 768px / 1440px; all primary actions visible, no sideways scroll, no horizontal clipping.
- Accessibility: field labels, keyboard navigation, visible focus, feedback via accessible status announcements.
- Run frontend lint, typecheck, unit tests and build. Existing backend lint/typecheck/tests/build must continue to pass.
- Compose config valid (`docker compose config`); HTTP proxy same-origin works. Use mock/fake provider ONLY for automated E2E, label it accurately.

4. Submit => queued => processing => completed, no fabricated percent/ETA.

6. Queue 3 files and verify a single worker sequentially handles jobs, UI remains responsive.

8. Refresh page: key requested again, job list recoverable after key re-entry.
9. Verify 401, oversized file, provider offline and frontend reload states.
10. Ensure frontend and API ports aren't accessible from LAN by default.
